# Регрессионный чек-лист Desktop — экраны 13″, 16″ и 27″

## Назначение

Чек-лист дополняет [полный desktop-регресс](./regression-desktop.md) и используется для проверки адаптивности брендов на компактном ноутбуке, большом ноутбуке и внешнем мониторе.

Диагональ сама по себе не определяет вёрстку. На результат влияют CSS viewport, системный scaling, DPR и zoom браузера. Поэтому в отчёте обязательно фиксируются и диагональ, и фактический viewport.

## Обязательная матрица экранов

| Профиль | Класс устройства | Обязательный CSS viewport | Zoom   | Ориентир реального устройства  | Главный риск                                              |
| ------- | ---------------- | ------------------------- | ------ | ------------------------------ | --------------------------------------------------------- |
| `D13`   | Ноутбук 13″      | `1280 × 720`              | `100%` | 13″ MacBook/Windows ultrabook  | Недостаток высоты, переполнение header, обрезанные модалы |
| `D16`   | Ноутбук 16″      | `1728 × 1000`             | `100%` | 16″ MacBook Pro/Windows laptop | Некорректные промежуточные breakpoints и растянутые формы |
| `D27`   | Монитор 27″      | `2560 × 1440`             | `100%` | 27″ QHD monitor                | Чрезмерное растяжение, пустоты, низкая плотность контента |

Дополнительные контрольные режимы при наличии времени:

- `1366 × 768` — распространённый компактный Windows laptop;
- `1920 × 1080` — распространённый 16–27″ Full HD экран;
- zoom `125%` на `1920 × 1080` — приближённая проверка системного scaling Windows;
- DPR реального устройства — фиксировать отдельно, но не считать заменой обязательному CSS viewport.

## Правила выполнения

- Проверять одну и ту же сборку, гео, locale и тип пользователя на всех трёх профилях.
- Guest и authorized выполнять в отдельных контекстах.
- Не изменять zoom во время одного профиля.
- Перед каждым профилем делать hard reload и возвращать страницу в верхнее положение.
- Проверять страницу без DevTools, затем при необходимости собирать Console/Network evidence.
- Горизонтальный scrollbar страницы считается дефектом, кроме специально горизонтальных компонентов.
- Контент не должен исчезать только из-за увеличения доступной ширины или высоты.
- `P0 FAIL` хотя бы на одном обязательном профиле означает `NO-GO` для desktop.
- `N/A` допустим только для функции, официально отключённой на бренде.

## Критерии завершения

- `GO`: все применимые `P0` прошли на D13, D16 и D27; P1-дефекты заведены и оценены.
- `NO-GO`: любой P0 недоступен хотя бы на одном обязательном профиле; есть горизонтальное переполнение, перекрывающий overlay или недостижимый submit/Close.
- `PARTIAL`: один из профилей или обязательных разделов не проверен; такой результат не считается полным desktop-регрессом.
