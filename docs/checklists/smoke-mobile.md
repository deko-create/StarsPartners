# Smoke-чеклист бренда — Mobile

## Назначение

Быстрая проверка доступности бренда и ключевых мобильных пользовательских сценариев после релиза, конфигурационных изменений или перед полным регрессом.

Проверки выполняются без реального пополнения, вывода средств и ставки. Эмуляция подходит для первичного smoke, но release gate желательно подтвердить минимум на одном реальном iOS- и одном Android-устройстве.

- Быстрый release gate: выполнить все применимые `P0` (ориентир — 25–35 минут).
- Расширенный smoke: выполнить `P0` и `P1` (ориентир — 50–90 минут на одну конфигурацию устройства).

## Статусы и приоритеты

- `PASS` — ожидаемый результат получен полностью.
- `FAIL` — воспроизводимый дефект продукта.
- `BLOCKED` — проверка невозможна из-за WAF, окружения, данных или внешнего сервиса.
- `N/A` — функция отсутствует у бренда по требованиям; требуется комментарий.
- `NOT RUN` — проверка еще не выполнялась.
- `P0` — критический release gate: отказ означает `NO-GO`.
- `P1` — важная smoke-проверка: отказ требует оценки владельца продукта перед релизом.

Нельзя маскировать дефект статусом `N/A` или `BLOCKED`. Для каждого такого статуса обязательна конкретная причина.

## Предусловия

- [ ] URL, окружение, разрешенное гео и конфигурация бренда подтверждены.
- [ ] Cloudflare/WAF допускает мобильный браузер; нет бесконечного challenge-loop.
- [ ] Подготовлены новый и существующий тестовые игроки, если регистрация доступна.
- [ ] Для платежных проверок задана валюта и доступен игрок с нужным статусом.
- [ ] Первый проход начинается с очищенными site data; авторизованные проверки — в отдельной сессии.
- [ ] Отключены блокировщики контента и режим экономии трафика.
- [ ] Основной проход выполняется в portrait; поворот проверяется отдельно.
- [ ] Известны допустимые ограничения провайдеров, гео, KYC и мобильных браузеров.

## Критерии завершения

- `GO`: все `P0` имеют `PASS`; для `P1 FAIL/BLOCKED` есть баги и принятое владельцем продукта решение.
- `NO-GO`: любой `P0 FAIL`; невозможны загрузка, регистрация/вход, мобильная навигация, каталог/игра, Sports/betslip или платежный экран.
- Прогон нельзя считать завершенным, пока `NOT RUN` остается у применимых `P0`.
- Если пройдена только эмуляция, это явно указывается в итогах как остаточный риск.

## Автоматизированная базовая проверка

Замените `<brand>` на slug бренда:

```bash
node scripts/qa-brand-run.js --brand=<brand> --mode=mobile --profile=core
```

Автоматический прогон дополняет чеклист, но не заменяет проверку на реальном устройстве, touch-поведения и визуальной компоновки.
